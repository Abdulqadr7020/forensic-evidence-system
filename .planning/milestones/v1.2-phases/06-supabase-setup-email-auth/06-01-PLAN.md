# Plan 06-01: Initialize Supabase and Email Auth Logic

## Goal
Set up the Supabase project connection and implement the core authentication logic (React Context, Auth hook, and standard Email/Password sign up and sign in).

## Context
- We are using Supabase as our backend authentication provider (Decision from ROADMAP.md).
- We are using React Context for auth state management.
- We are implementing standard Email & Password authentication (Magic Links deferred).

## Implementation Steps

### 1. Install Supabase Client
- [ ] Run `npm install @supabase/supabase-js` to add the official client library.

### 2. Configure Environment Variables
- [ ] Create `.env.local` in the project root.
- [ ] Add `VITE_SUPABASE_URL` and `VITE_SUPABASE_ANON_KEY` placeholders.
- [ ] Document in README.md that these variables are required.

### 3. Initialize Supabase Client
- [ ] Create `src/lib/supabase.ts`.
- [ ] Initialize and export the Supabase client using the environment variables.

### 4. Create Authentication Service
- [ ] Create `src/services/auth.ts`.
- [ ] Implement wrapper functions for `signUp`, `signIn`, and `signOut` utilizing the initialized Supabase client.

### 5. Implement React Context AuthProvider
- [ ] Create `src/contexts/AuthContext.tsx`.
- [ ] Define the `AuthContext` with session and user state.
- [ ] Create the `AuthProvider` component.
  - Setup an initial session fetch inside a `useEffect`.
  - Subscribe to `onAuthStateChange` to automatically handle session updates.
- [ ] Create a custom hook `useAuth` to safely consume the context.

### 6. Wrap Application with AuthProvider
- [ ] Update `src/App.tsx` (or `src/main.tsx`) to wrap the root layout/router inside the `<AuthProvider>`.

## Verification Steps
- [ ] Verify that the application boots up without crashing after `AuthProvider` is added.
- [ ] Verify that `@supabase/supabase-js` is correctly listed in `package.json`.
- [ ] (Manual Test) Check that no console errors appear regarding Supabase missing URL if env vars are temporarily provided.
