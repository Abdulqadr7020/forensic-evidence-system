# Plan 08-01: Premium Glassmorphic Auth UI and Route Protection

## Requirements
- AUTH-03: Route protection
- UI-01: Glassmorphic UI

## Goal
Build the sleek, dark-mode glassmorphic authentication view (Sign In & Sign Up) with Google OAuth and Email/Password credentials, and implement route protection so unauthenticated users are gated behind authentication while authenticated users are directed to the application dashboard.

## Context
- **Requirements Covered:**
  - AUTH-03: Route protection (unauthenticated users gated to login, authenticated users access views)
  - UI-01: Glassmorphic UI (dark-mode, glass cards, backdrop blur, ambient radial illumination)
- **Locked Decisions (from 08-CONTEXT.md):**
  - D-01: Centered Floating Glass Card with ambient dark backdrop and subtle radial glow.
  - D-02: Bottom Text Link Switcher with smooth cross-fade transition between Sign In and Sign Up.
  - D-03: Minimal Logo & Welcome Header with Sentinel DMS shield brand mark.
  - D-04: Google on Top ("Continue with Google" primary social action, illuminated divider, email/password form).
  - Builder's Discretion: Route protection state gate in `App.tsx`, password visibility toggle, error displays, and guest exploration option.

## Implementation Steps

### 1. Build Centered Glassmorphic AuthView Component
- [x] Create `src/views/AuthView.tsx`:
  - Fullscreen dark ambient viewport with subtle cyber grid and centered cyan/emerald radial glow.
  - Centered floating glassmorphic card with `backdrop-blur-xl`, semi-transparent dark surface, and refined border illumination.
  - Minimal header featuring Sentinel DMS shield logo and context-sensitive welcome message.
  - "Continue with Google" button at top calling `signInWithGoogle()`.
  - Illuminated divider ("or continue with credentials").
  - Form with email input, password input with toggleable show/hide eye icon, and submit button with loading spinner.
  - Bottom switcher link toggling between Sign In and Sign Up modes with smooth Framer Motion transitions.
  - Error banner displaying `authError` or input validation errors.
  - Optional subtle "Explore as Guest" bypass link.

### 2. Implement Route Protection in App.tsx
- [x] Update `src/App.tsx`:
  - Gate the protected application views based on `isAuthenticated` (and guest mode).
  - While `loading` is true, display a sleek, non-jarring loading transition.
  - If unauthenticated, render `<AuthView />`.
  - If authenticated (or guest active), render `<AppContent />`.
  - Wrap view switching in Framer Motion `AnimatePresence` for smooth cross-fading.
  - Ensure logging out immediately redirects back to `<AuthView />`.

### 3. Build & Visual Verification
- [x] Run `cmd.exe /c "npm run lint"` (`tsc --noEmit`) to verify type safety.
- [x] Run `cmd.exe /c "npm run build"` to verify the Vite production bundle.
- [x] Verify that unauthenticated access shows the auth card, Google login triggers properly, email login/signup works, and authenticated state displays the dashboard.
