# Plan 10-01: Express Backend API & Supabase Integration

## Objective
Build the Express backend server endpoints to handle multipart file uploads, encrypt payloads using the existing `server/crypto.ts` module, upload to Supabase Storage, and save field-level encrypted records to the database. Provide a download endpoint to stream decrypted files.

## Dependencies
- `multer` package must be installed.
- Supabase project must be configured with a Service Role key to bypass RLS for the backend operations (or pass the Bearer token down).
- The `evidence` table and `evidence-vault` bucket must exist in Supabase.

## Tasks

### 1. Install Dependencies
**Description:** Install `multer` for multipart form parsing, and its TypeScript types.
**Command:** `npm install multer cors && npm install -D @types/multer @types/cors`
**Expected Outcome:** `multer` and `cors` are available in the project.

### 2. Configure Express Server & Middleware
**Description:** Create `server/index.ts` to initialize the Express application. Configure CORS, JSON parsing, and Multer memory storage. Set a reasonable file size limit (e.g., 50MB) on the Multer instance to prevent memory exhaustion as per decision D-01.
**Expected Outcome:** Express server runs with Multer configured for memory buffering.

### 3. Initialize Supabase Admin Client
**Description:** Create `server/supabase.ts` that exports a Supabase client initialized with the `SUPABASE_URL` and `SUPABASE_SERVICE_ROLE_KEY` (or anon key depending on auth flow). This client will be used for backend storage and database writes.
**Expected Outcome:** A working Supabase client instance available for server routes.

### 4. Implement Upload Endpoint (`POST /api/evidence/upload`)
**Description:** Add a POST route that accepts a multipart upload (using Multer).
1. Read the file buffer from `req.file`.
2. Encrypt the buffer using `encryptFileBuffer(req.file.buffer)`.
3. Extract `caseId`, `title`, and `description` from `req.body`.
4. Upload the packed encrypted buffer to Supabase Storage at `evidence-vault/${caseId}/${fileId}.enc` (Hierarchical layout per D-02).
5. Encrypt `title` and `description` using `encryptField()`.
6. Insert a record into the `evidence` table with the encrypted metadata, file path, and both SHA-256 digests.
**Expected Outcome:** Files are successfully encrypted and persisted to Supabase, along with encrypted metadata.

### 5. Implement Download Endpoint (`GET /api/evidence/:id/download`)
**Description:** Add a GET route to retrieve and decrypt evidence.
1. Fetch the evidence record from the DB to get the `file_path` and `content_type`.
2. Download the encrypted file blob from Supabase Storage.
3. Decrypt the blob using `decryptFileBuffer()`.
4. Set the `Content-Type` header and stream/send the plaintext buffer back to the client.
**Expected Outcome:** Encrypted files can be retrieved and viewed/downloaded cleanly.

### 6. Verification
**Description:** Add tests or use an API testing tool (like a quick Node.js script) to hit the upload endpoint with a dummy file and metadata, verify it returns 201, then hit the download endpoint and verify the file contents match exactly.
**Command:** `npx tsx server/test-upload.ts` (create a simple throwaway script for this).
**Expected Outcome:** End-to-end upload and download works cryptographically.

## Definition of Done
- Express server is functional.
- Multer processes memory buffers.
- File buffers and fields are encrypted using AES-256-GCM before hitting Supabase.
- Download endpoint successfully verifies and decrypts files.
