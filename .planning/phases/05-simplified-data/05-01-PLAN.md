# Plan 05-01: Update Data Fixtures with Simple Terminology

## Goal
Rename all evidence files, case titles, and related terminology to be short, simple, and easy to understand in plain English.

## Approach
Update the mock data directly in `src/data/fixtures.ts` to reflect the user's preference for realistic legal names over complex developer jargon.

## Tasks

### 1. Update Case Data (`FIXTURE_CASES`)
- **File**: `src/data/fixtures.ts`
- **Action**: 
  - Simplify the `title` for each case (e.g., "Apex Syndicate Operation" -> "Robbery Case", "Operation Silent Night" -> "Fraud Investigation").
  - Simplify the `description` for each case to plain English.

### 2. Update Document Data (`FIXTURE_DOCUMENTS`)
- **File**: `src/data/fixtures.ts`
- **Action**: 
  - Update the `title` for each document to a realistic legal name (e.g., "Arrest Report - Suspect John Doe.pdf", "Search Warrant - Main St.pdf").
  - Ensure the nomenclature looks like standard police records, removing confusing technical tags.

## Edge Cases
- Ensure the types and interfaces (e.g., `DocumentRecord`, `CaseRecord`) match the updated data format if any structural changes occur, though we primarily expect to only change string values.

## Acceptance Criteria
- [ ] `src/data/fixtures.ts` contains simple, plain English titles for cases and documents.
- [ ] The application compiles without errors.
- [ ] Developer jargon is entirely replaced in the mock data objects.
