# Plan 09-01: Node.js AES-256-GCM Crypto Engine & Master Key Configuration

## Requirements
- **CRYPTO-01**: System can encrypt evidence files and data payloads using Node.js inbuilt `node:crypto` AES-256-GCM with a 32-byte master key, unique 12-byte random IV, and 16-byte authentication tag.
- **CRYPTO-02**: System computes SHA-256 digests for plaintext and ciphertext payloads, enabling verified digital chain-of-custody.
- **CRYPTO-03**: System authenticates and decrypts payloads via `node:crypto.createDecipheriv` with GCM tag verification, rejecting tampered data.

## Goal
Implement the core server-side cryptographic engine in `server/crypto.ts` using Node.js inbuilt `node:crypto` module, providing AES-256-GCM authenticated encryption/decryption, SHA-256 digest calculation, 12-byte CSPRNG IV generation, 16-byte authentication tag verification, dual-envelope packaging (packed Buffer for evidence files, structured JSON/string for database fields), master key environment validation, and an automated verification test runner in `server/crypto.test.ts`.

## Context
- **Locked Decisions (from 09-CONTEXT.md):**
  - **D-01: Master Key Format:** 64-character hex string (32 bytes / 256 bits) in `ENCRYPTION_KEY` env var in `.env.local`. Strict startup validation halts with an explicit error if missing or invalid length.
  - **D-02: Payload Envelope Format:** Dual format:
    1. Packed Buffer `[12-byte IV][16-byte Auth Tag][Ciphertext]` for evidence file blobs.
    2. Structured representation `{ iv, authTag, ciphertext }` or compact string `gcm:${iv}:${authTag}:${ciphertext}` for database fields.
  - **D-03: Tamper Detection & Error Policy:** Custom `CryptoTamperError` class returning explicit `TAMPER_DETECTED` status and forensic audit details whenever GCM authentication fails or payload tampering is detected.
  - **D-04: Automated Verification Script:** Standalone test runner script `server/crypto.test.ts` runnable with `npx tsx server/crypto.test.ts` and registered in `package.json` as `npm run test:crypto`.

## Artifacts this phase produces
- `server/types.ts`: `CryptoTamperError`, `EncryptedFilePayload`, `EncryptedField`, `DecryptedFilePayload`
- `server/crypto.ts`: `getMasterKey`, `sha256`, `encryptFileBuffer`, `decryptFileBuffer`, `encryptField`, `decryptField`
- `server/crypto.test.ts`: Automated test suite testing key validation, round-trip encryption, SHA-256 hashing, tamper rejection, IV uniqueness

<task id="3" name="implement-core-crypto-module">
  <read_first>
    - server/types.ts

  <action>
    Implement `server/crypto.ts` using Node.js inbuilt `node:crypto` (CRYPTO-01, CRYPTO-02, CRYPTO-03, D-01, D-02, D-03).
    Load environment variables with `dotenv/config`.
    Implement `getMasterKey()`: reads `process.env.ENCRYPTION_KEY`, validates it matches `/^[0-9a-fA-F]{64}$/`, converts to 32-byte `Buffer.from(keyHex, 'hex')`. If missing or length != 32 bytes, throws an immediate `Error('FATAL: ENCRYPTION_KEY must be a 64-character hex string (32 bytes)')`.
    Implement `sha256(data: Buffer | string): string`: computes SHA-256 hex digest using `crypto.createHash('sha256')`.
    Implement `encryptFileBuffer(plaintext: Buffer): EncryptedFilePayload` (D-02):
    - Computes `sha256Plaintext = sha256(plaintext)`.
    - Generates 12-byte random IV via `crypto.randomBytes(12)`.
    - Creates cipher via `crypto.createCipheriv('aes-256-gcm', key, iv)`.
    - Produces ciphertext via `Buffer.concat([cipher.update(plaintext), cipher.final()])`.
    - Extracts 16-byte tag via `cipher.getAuthTag()`.
    - Packs envelope: `packedBuffer = Buffer.concat([iv, authTag, ciphertext])`.
    - Computes `sha256Ciphertext = sha256(packedBuffer)`.
    Implement `decryptFileBuffer(packedBuffer: Buffer): DecryptedFilePayload` (D-02, D-03):
    - Asserts `packedBuffer.length >= 28` (12 bytes IV + 16 bytes Tag).
    - Extracts `iv = packedBuffer.subarray(0, 12)`, `authTag = packedBuffer.subarray(12, 28)`, `ciphertext = packedBuffer.subarray(28)`.
    - Computes `sha256Ciphertext = sha256(packedBuffer)`.
    - Creates decipher via `crypto.createDecipheriv('aes-256-gcm', key, iv)`.
    - Sets auth tag via `decipher.setAuthTag(authTag)`.
    - Decrypts inside try-catch. If `decipher.final()` throws, catches error and throws new `CryptoTamperError('Authentication tag mismatch or tampered payload', { sha256Ciphertext })`.
    - Computes `sha256Plaintext = sha256(plaintext)`.
    Implement field-level encryption helpers (D-02):
    - `encryptField(text: string): EncryptedField`: encrypts UTF-8 string with fresh 12-byte IV, returns hex strings for `{ iv, authTag, ciphertext, serialized: 'gcm:${iv}:${authTag}:${ciphertext}' }`.
    - `decryptField(payload: EncryptedField | string): string`: parses structured or serialized format, decrypts text, throws `CryptoTamperError` if tag check fails.
  </action>

    - `encryptFileBuffer` produces packed Buffer prefixed with 12 bytes IV and 16 bytes auth tag.
    - Decryption validates auth tag and throws `CryptoTamperError` on invalid tag or corrupted ciphertext.
  </acceptance_criteria>

    1. Key Validation: validates that a 64-character hex key loads correctly, and malformed/short keys throw fatal errors.
    2. Buffer Encryption/Decryption Round-Trip: encrypts a sample binary buffer and verifies that `decryptFileBuffer` produces identical plaintext bytes.
    3. SHA-256 Chain of Custody: verifies `sha256Plaintext` matches `sha256(original)` and `sha256Ciphertext` matches `sha256(packedBuffer)`.
    4. Ciphertext Tamper Rejection: flips a byte in the ciphertext payload of `packedBuffer` and asserts that `decryptFileBuffer` throws `CryptoTamperError` with `code === 'TAMPER_DETECTED'`.
    5. IV Tamper Rejection: modifies a byte in the 12-byte IV and asserts decryption throws `CryptoTamperError`.
    6. Auth Tag Tamper Rejection: modifies a byte in the 16-byte auth tag and asserts decryption throws `CryptoTamperError`.
    7. IV / Nonce Uniqueness: performs 100 sequential encryptions of the same plaintext and asserts 100 unique IVs and ciphertexts are produced.
    8. Field-Level Encryption Round-Trip: encrypts text strings using `encryptField` and verifies `decryptField` recovers original strings from both object and serialized formats.
    Print concise test summary and exit with code 0 on success, code 1 on failure.
  </action>
